2. **Quadratic active CPU paths precede any useful timing.** `bench/star-integrate/star_integrate.cpp:149` linearly finds each request's frame offset: O(JF) per dispatch. Lines 327 and 387 scan frames per read: O(W²) per window. Lines 400 and 425 scan *all window jobs* per suppression/lookup: O(WJ), including misses. For the structural example W=32,768 and four candidates/read, `begin_map` alone visits 536,887,296 frames; consuming all J=131,072 jobs visits 8,590,000,128 jobs. These are loop counts, not measurements. Use an ordered frame cursor, frame-local job ranges and a frame-offset map or contiguous-frame traversal; preserve exact field/byte equality. Exercise the real coordinator with visit counters showing linear growth before the expensive host gate. This is host algorithmic overhead, not kernel tuning.

3. **Strict mode hides invalid GPU successes.** `bench/star-integrate/star_integrate.cpp:184` marks malformed successes invalid, then lookup skips them at line 428 and stock fallback runs. `crates/umstar/src/lib.rs:473` converts other malformed successes into a generic GPU call failure, likewise CPU-resolved at coordinator line 172. The oracle at `bench/star-integrate/make_star_integrate.py:26` therefore never sees these defects. Make successful-result bounds defects fatal in strict mode, including the backend rejection path; retain defect diagnostics outside strict mode. Validate backend containment against `q.low/q.high`, too, not just global nSA.
